# ProcessorMetadataContract v0.1

## Purpose

Defines how metadata produced by processors is stored.

---

## Structured Metadata

Metadata required by core system logic MUST be stored in structured tables.

Examples:

- duration_ms
- video_codec
- resolution

These fields are indexed and queryable.

---

## Flexible Metadata

Processor-specific outputs MAY be stored as JSON payloads. Flexible processor outputs MUST be stored in a processor_outputs table containing:

- processor_id
- target_type
- asset_id or media_id
- payload_json
- created_at

Examples of payload content:

- scene classification
- ad break candidates
- speech transcripts

---

## Metadata Ownership

Metadata fields are owned by one of:

**Source**  
Imported during container discovery.

**Processor**  
Generated by metadata processors.

**Operator**  
Modified manually by station operators.

Processors MUST NOT overwrite operator-owned fields. Processors MAY update fields they own when media changes.

---

## Implementation notes (compliance)

- **Structured metadata** is written to Asset and child tables (AssetProbed, AssetEditorial) from the processor runtime apply step; only keys declared in the processor capability `produced_metadata` are applied.
- **Flexible output** is written to the `processor_outputs` table: one row per `(processor_id, target_type, target_id)` with `payload_json` and `created_at`; the runtime upserts from `ProcessorResult.flexible` after a successful job.
- **Ownership** is enforced in the runtime: a `FIELD_OWNERSHIP` mapping (e.g. `approved_for_broadcast`, `operator_verified` → operator; `duration_ms`, `video_codec`, etc. → processor) is applied when merging processor results into the context and when persisting to the asset; keys with ownership `operator` are skipped so processors do not overwrite operator-owned fields.
